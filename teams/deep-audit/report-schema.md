# Deep audit report contract (version 1)

Return exactly one JSON object (no code fences) with these keys:

```json
{
  "schema_version": 1,
  "scope": {"requested": "string", "examined": ["path or component"], "excluded": ["path or component and reason"]},
  "inventory": {"stack": ["observed technology/runtime"], "structure": ["directory or module layout"], "components": ["component, role, and files"], "entry_points": ["executable or package entry point"], "dependencies": ["declared dependency, version, and examined usage"], "test_suites": ["suite, command, type, and availability"], "boundaries": ["trust, execution, or scope boundary"]},
  "method": {"phases_completed": ["inventory", "architecture", "correctness", "security", "dependencies", "performance", "simplicity", "tests", "independent_review"], "checks": [{"kind": "Serena|read|glob|grep|documentation|scanner|test", "target": "string", "result": "string", "command": "string|null", "exit_code": "integer|null"}]},
  "execution": {"target_commit": "string|null", "models_used": [{"agent": "string", "configured_model_id": "string|null", "model_id": "provider/model or unknown", "reasoning": "observed configuration variant or unknown", "identity_source": "session_database|session_metadata|visible_tui|specialist_statement|unknown", "provider_attested": false}], "tool_versions": {"tool": "version"}, "commands": [{"command": "string", "exit_code": "integer|null", "status": "passed|failed|completed_with_findings|not_executed"}]},
  "findings": [{"id": "DA-SEC-001", "status": "CONFIRMED|PROBABLE|UNVERIFIED|FALSE_POSITIVE|NOT_EXECUTED", "severity": "critical|high|medium|low|info", "confidence": "high|medium|low", "category": "architecture|correctness|security|dependencies|performance|dry|overengineering|simplicity|tests|technical_debt|other", "title": "string", "files": ["path"], "symbols": ["function/class"], "evidence": [{"path": "string", "lines": "start-end", "observation": "string"}], "observed_behavior": "string", "expected_behavior": "string", "root_cause": "string", "impact": "string", "tests": [{"command": "string", "result": "passed|failed|not_executed", "exit_code": "integer|null"}], "recommendation": "string", "alternatives": ["string"], "regression_risk": "string", "dependencies": ["finding ID"], "priority": "P0|P1|P2|P3", "complexity": "low|medium|high", "verification": "string", "limitations": ["string"]}],
  "coverage_gaps": ["string"],
  "limitations": ["string"],
  "summary": "string"
}
```

All keys are mandatory; arrays may be empty (including completed phases and inventory lists for partial audits). The inventory object is required even when its lists are empty; leave unknown items empty and explain missing inventory in `coverage_gaps` rather than guessing. Every field must have the type and enum value shown above. Record the actual runtime model ID or `unknown`, the independently observed configured ID or `null`, and the source of the runtime identity. `provider_attested` must remain false unless provider-side attestation is actually available; an OpenCode session record is runtime evidence, not provider attestation. The legacy `reasoning` field records only an observable configuration variant (e.g. `xhigh`, `default`) or `unknown`; it is **not** evidence of hidden reasoning or model behavior. Every phase name must be one of the listed phases. Every check, finding, evidence item and test result must match its declared shape and enums. Invalid or incomplete reports must be rejected with an error naming the invalid field; they must never be saved partially. Cite existing file paths and line ranges for CONFIRMED and PROBABLE repository findings; if evidence cannot be located, move the hypothesis to `coverage_gaps`. Distinguish observed behavior from inferred impact. Sort findings by severity, then ID. Do not claim tests, scanners, phases, or other work ran unless they actually ran: use `not_executed` for command/test status and omit incomplete phases from `phases_completed`. Executed scanner commands that return a findings-specific nonzero exit code use `completed_with_findings`, not an infrastructure-failure claim. Command/test exit codes must be null if and only if the status is `not_executed`; a check without a command must have a null exit code. Never include secrets, credential values, or full sensitive file contents; redact excerpts. `limitations` explains any missing phase or unavailable tool/model. An empty findings array does not imply a clean bill of health. For Django test evidence, identify SQLite as the executed backend and explicitly mark PostgreSQL/MySQL-specific behavior as `NOT_EXECUTED`.

Use `dry` only for duplication findings, `overengineering` (or legacy `simplicity`) only for unnecessary complexity, and `technical_debt` for debt; `dependencies` and `other` appear in the technical-debt section. A finding appears in exactly one category section, as well as the roadmap and verification evidence. Dependencies contain existing finding IDs only (use `[]` for none); cycles and lower-priority prerequisites are invalid. The roadmap groups P0 through P3 and places prerequisites before dependents within each priority. Do not disguise a lower-priority prerequisite as a higher-priority remediation item: align priorities before saving.
